# Fase 1 — Base de la plataforma: Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Una app estática (GitHub Pages) donde se carga un DOCX/PDF/TXT, el analizador local extrae temas, glosario, procesos, preguntas, alertas y fuentes con citas verificadas, y cada tema se explora en un mapa de conceptos 3D con selección, foco y ficha.

**Architecture:** Ingesta por formato → `DocumentModel` (bloques con id + texto canónico). `AnalysisProvider` local → `StudyPlan` (validado con zod) → verificador de citas. Catálogo de escenas con emparejamiento por palabras clave; en esta fase solo existe la entrada alternativa `alternativa.mapa-conceptos`. Store zustand en memoria; visor React Three Fiber; interfaz React + Tailwind.

**Tech Stack:** Node 24, Vite, React 18, TypeScript (strict), Tailwind CSS v4 (`@tailwindcss/vite`), zustand, zod, three, @react-three/fiber, @react-three/drei, mammoth, pdfjs-dist, Vitest + jsdom + @testing-library/react.

**Spec:** `docs/superpowers/specs/2026-11-17-plataforma-aprendizaje-3d-design.md` (secciones 5.1–5.6, 5.8, 5.9, fase 1 de la sección 7).

## Global Constraints

- Solo frontend; publicable en GitHub Pages. Vite `base` = `'./'` (rutas relativas, funciona en cualquier nombre de repositorio).
- Prohibido usar `localStorage`, `sessionStorage`, `indexedDB`, `document.cookie` o cualquier persistencia. zustand **sin** middleware `persist`.
- Sin router de URL; ningún dato del usuario en la URL.
- Ninguna clave ni secreto en el código.
- Interfaz en español. Tema oscuro, acento cian (`#22d3ee`).
- Toda `Afirmacion` con `origen: 'documento'` lleva `cita` literal y `blockId`; si la cita no se encuentra en el texto canónico pasa a `origen: 'complementario'` con `verificada: false`.
- Los títulos tipo índice (`/^(índice|contenido|tabla de contenido)/i`) no generan temas.
- Archivos admitidos en esta fase: `.docx`, `.pdf`, `.txt`, `.md`. Otros ⇒ `UnsupportedFormatError` con mensaje visible.

## Review Focus

1. **Documento sin títulos** (texto plano corrido): debe producir un único tema "Documento completo" y un mapa de conceptos (posiblemente vacío con mensaje), nunca una pantalla en blanco ni un error. → test en Task 6.
2. **PDF escaneado sin texto**: `parsePdf` devuelve 0 bloques ⇒ la app muestra "Este PDF no contiene texto seleccionable; el reconocimiento de texto (OCR) llegará en una fase posterior", no un plan vacío silencioso. → test en Task 4.
3. **Tildes, comillas tipográficas y espacios múltiples en citas**: la verificación normaliza ambos lados; una cita con "á" frente a texto con "á" descompuesto (NFD) debe verificarse. → test en Task 5.
4. **Archivo corrupto o con extensión engañosa** (`.docx` que no es ZIP): error legible "No se pudo leer el archivo", la sesión anterior sigue intacta. → test en Task 4 y Task 9.
5. **Concepto repetido** (mismo término en lista y en tabla, p. ej. "Borramiento"): un solo concepto con varias afirmaciones, no dos nodos. → test en Task 6.

**Interfaces:**

- Produces:

Reglas:
- **Temas**: cada heading que no sea índice; `nivel` = level; `padreId` = tema del heading de nivel menor anterior; `blockIds` = bloques hasta el siguiente heading de nivel ≤; `resumen` = primer párrafo del tema como `Afirmacion` (cita = texto completo). - **Conceptos** desde (a) `list-item` con patrón `^([^:]{2,60}):\s+(.+)$`; (b) tablas de 2 columnas cuya cabecera de la 2.ª columna casa con `/descrip|defini|signific|funci|caracter|edad|qué|que es|meaning|description|definition|function/i` ⇒ cada fila (sin cabecera) = término→definición; (c) cualquier otra tabla de 2+ columnas ⇒ `Comparacion` (incluye la de 3 columnas). Tipo: `'termino'` por defecto. Duplicados por `normalize(nombre)` se fusionan: un concepto, varias `definicion`. Cita = texto literal de la definición.
